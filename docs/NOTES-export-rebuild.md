# 2026-11-02.export-rebuild

本次仅修改地图导出器。首次开屏恢复原先的多色流动渐变，保留固定画布展开、平滑进度与动画缓存。首次向导的三行截图继续保留。

固定导出来源：程序目录下随附的 `runtime/`（按字节保留的固定工具链）。程序检查 map-export.exe 与 dfmap.dll 的 SHA256，不再采用历史配置中的其他导出器；便携包提供同字节工具链作为搬迁后的来源。

普通地图导出和「进 UE」均增加完整源渲染状态阶段。批处理直接调用该目录原始 dfmap.dll 的公共 embedding API、原始关卡提取及 JSON 序列化，加载一次游戏包，读取各关卡、类模板和实例覆盖。原始几何及 lights.json 继续由固定版本导出器生成；新的 render_state.json 补充灯光单位、色温、间接光、体积雾专用标记、源雾设置、限定范围的后处理以及游戏保存的相机。游戏隐藏辅助对象的状态现在保留到 Blender / UE。

`source-render/raw/` 保留原始关卡与模板 JSON，`source-render/assets/` 按原路径保留游戏 lightmap、可选 mip、局部烘焙体积以及引用的预烘焙阴影文件，每个文件记录 SHA256。它们不是可以直接拖入标准 UE 的未烘焙工程资源。

CollectionRoom验证：重新导出 31 个关卡，130 条灯光、49 盏仅影响体积雾的灯、1 处有范围限制的后处理、27 个源相机；保留 126 个烘焙/阴影载荷，317,247,001 字节。UE 5.4 实测 129 个普通灯组件的亮度和单位、色温与雾灯表面通道隔离；核对源雾密度 0.004、衰减 0.7、距离 5000，以及后处理范围和优先级。完整 Blender → UE 导入、保存与原相机出图通过。26 项回归通过。

渲染边界必须区分：导出源数据保持原值，标准 UE 预览仍是兼容渲染。游戏专用 PRT、预烘焙雾深度和部分 DarknessCorrection / MobileLensFlare 字段不能直接在标准 UE 上运行。雾灯在预览中使用独立表面通道、实时体积阴影，并将缺少游戏深度遮罩的高散射限制在原生 UE 范围；原始高散射值完整保留在 render_state.json，预览替代值写在 lighting_report.json 的 fog_compatibility 中。不能据此宣称画面与游戏完全一致。

预览曝光补偿仅影响图片，不修改源导出。0 EV 是默认，验证图片另测试了 -3 EV，并在 render_report.json 记录。自动视角会优先使用游戏保存的相机。完整导出后请使用本版重新导入，旧 lights.json 摘要不含此次补回的信息。

纯导入阶段临时关闭距离场渲染分配，避免 NullRHI 为地图分配巨大内存；不会修改工程最终渲染设置。错误、取消和不完整的源状态会使任务失败，不能继续显示旧地图为成功。
