# Blender 工程、实时地图预览与 WeGame 地图修复

版本：`1.0+2026-11-03.blender-preview-wegame-fix`

## 使用

- 地图导出页选择「导出到 Blender」或「导出到 UE」，再选择地图并开始导出。Blender 模式不需要配置 UE。
- Blender 模式会保存独立的地图 `.blend` 主文件和 `assets` 分块；贴图打包进分块。移动工程时请移动整个工程目录。可在工程管理页打开、移动、重命名和删除。
- 导出窗口新增「3D 预览」。生成模型后可旋转、缩放、平移，按分块过滤。橙色表示正在处理，绿色表示当前步骤完成。预览使用原始网格的简化三角面，不读取整张贴图；完整导出网格保留不变。
- 在设置选择 WeGame 的 `DeltaForce/Content/Paks` 后，软件会自动同时挂载同一安装中的 `PackContent/Paks` 和 `Saved/Dolphin` 下载更新资源。点击「扫描游戏地图」或模型资源页的「扫描地图」刷新列表。
- Brakkesh的完整地图代号为 `Brakkesh_Long3`；Collapse为 `Collapse`。同时支持源地图、BuildMaps_HD 和 BuildMaps 目录中的关卡。

## 修复

- MA1 日志里的具体错误为分块分析退出时找不到 `ZstdSharp 0.8.8.0`。辅助程序现在显式声明、提前加载并校验此依赖，同时支持从导出器目录和辅助程序目录查找依赖。
- 每次导出使用独立配置快照，切换游戏安装或重新扫描不会改变已经运行的分块所用配置。
- 地图扫描不再只读取 BuildMaps_HD；扫描失败或清单截断时明确报错。物理共享目录和 Engine 模板不会作为游戏地图显示。
- Blender 保存后重新打开每个分块和主文件，校验网格、变换、材质槽、贴图打包及相对库链接。重复 HLOD 的处理与现有导出策略一致。
- Blender 准备工作不会改写此前 UE 工程的完成报告。

## 验证范围

- 使用用户指定 E 盘 WeGame 安装及其更新包，确认实际存在Brakkesh、Collapse关卡，并用游戏内数据表校对中文名称。
- MA1 六个原生分析进程全部正常退出：共 930 个过滤后的源关卡、44,091 个模型实例；也验证了导出器目录缺少 ZstdSharp 时使用辅助程序自带依赖。此项验证覆盖日志中的失败步骤，未把它表述为整张 MA1 已完成 UE 导入。
- 六个BombDefusal Mansion真实 Blender 分块打包并重开、主工程重新链接并重开通过：4,631 个网格对象、2,365 个打包图像记录、138 个支持类型的源灯光。
- 实际 GLB 创建 Blender 场景及过程中预览快照生成通过；GTX 1650 实测六分块 GPU 预览的旋转、缩放和过滤。
- 普通交互控件采用 FluentPy 原生组件；3D 画布使用 OpenGL，显卡不可用时退回简化软件绘制。

Blender 灯光保留支持的原始光源类型和参数记录，但游戏专有的烘焙、PRT 与曝光模型不能等价搬入 Blender。预览只用于查看地图形状和处理状态，不作为最终光照成品。
