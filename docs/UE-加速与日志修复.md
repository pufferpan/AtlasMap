# UE 加速与日志修复

本次CollectionRoom失败发生在贴图导入期间，UE 日志记录了 `DXGI_ERROR_DEVICE_REMOVED` 和 GPU Timeout。新版导入命令使用 `-nullrhi`，准备资源时不创建 GPU 渲染窗口；打开导入结果仍使用正常渲染的编辑器。

- 文件检查与校验采用线程池，界面可选择 1–16 个准备线程，上限受 CPU 数量限制。
- 资源以有界批次提交给 UE，支持的格式启用引擎异步导入。所有 UObject 操作留在引擎主线程。
- 资源批量保存，状态检查点按间隔更新，减少逐资源保存和小文件写入。
- 导入、源灯光及碰撞在同一次 UE 启动中完成，减少重复加载整个关卡。
- 重试复用已验证的资源；网格新增文件指纹校验，避免旧网格被误当成新产物。
- 完成报告带每次运行的唯一标识，失败或旧报告不能冒充本次成功。未完成的部分关卡不能作为成功结果打开。

导出窗口现在直接以小窗口显示，内部日志始终可见。长路径和报错按窗口宽度换行，可选中或点击「复制日志」。窗口保留最近 2,000 条日志，完整过程持续写入该地图导出目录的 `pipeline.log`。

本机验证使用这次失败的CollectionRoom资源，在独立工程重新导入 528 张贴图、220 个网格和全部材质、865 个场景对象，并完成灯光和碰撞，UE 阶段总耗时 159.36 秒。其中贴图 12.77 秒、网格 89.92 秒。不同地图、磁盘和缓存状态的耗时会有差别。

验证结果位于 `work/ue_fast_20261101/CollectionRoom_ue/ue_import_result.json`；完整日志位于 `work/ue_fast_20261101/full-fast-validation.log`。原工程和正在打开的 UE 编辑器未被测试覆盖。
