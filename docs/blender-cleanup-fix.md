# Blender 模型输出与残留清理修复

版本：1.0+2026-11-03.blender-cleanup-fix

Dam_Iris_Long3 的第 10 步在 Blender 5.2.2 LTS 读取贴图尺寸时崩溃。调用 `image.size` 会触发 PNG 像素解码并保留缓冲区，两个失败分块的浮点像素存储估算分别约 15.6 GB 和 14.6 GB。现在从已有 PNG/JPEG 编码数据的文件头读取尺寸，不触发像素解码；导出的贴图字节和校验值保持一致。

失败或取消后的清理确认框曾被 Qt 当成最后一个普通窗口：主窗口隐藏、导出窗口属于工具窗口，确认框关闭后会导致程序自动退出，后台清理因而被中断。确认框现在不会触发应用退出；清理期间也不能直接关闭主窗口。清理进度会显示在任务日志和导出窗口中，无法删除的文件会记录具体原因。

清理的扫描、校验和删除统一使用 Windows 扩展路径，支持超过 260 字符的源资源路径。范围仍限于导出开始后新增、确认时未被修改的文件，保留已有工程、日志、后续修改的文件和链接目标。

UE 导入现在额外按实际贴图尺寸、FBX 体积估算每块内存，并同时检查物理内存和 Windows 提交余量。大分块在 16 GB 机器上逐块进入 UE，空间充足的机器仍可多进程处理；分块数量和各自的日志不变。

验证：252 项回归测试通过，其中包含真实应用事件循环下隐藏主窗口、关闭确认框并等待后台删除完成的回归，以及长路径、占用文件、链接替换、已有文件保护和 UE 导入内存预算。已用当前 Dam_Iris_Long3 的六个真实保留分块完成第 10—13 步，全部 Blender 进程成功退出，FBX 文件尾、贴图 SHA256、材质编译和分块目录校验均通过。9493 条贴图记录中的 3322 张不同贴图全部通过独立像素解码检查。UE 后续验证使用 I 盘新建独立工程，原 G 盘工程保留；完成情况以对应完整导出日志和结果报告为准。
