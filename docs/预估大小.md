# 预计大小是怎么算的

预估只看**元数据**，不会为了估算去解一遍地图。按数据可信度分成三档，界面上的说明文字会
告诉你是哪一档：

| 依据 | 出现条件 | 说明 |
| --- | --- | --- |
| `history` 实测 | 这张图以前成功导出过 | 直接拿上次导出的真实字节数，只有贴图部分按当前质量档位折算；同一档位下误差 ±12% |
| `source` 已有源导出 | 输出目录里有 `merge_report.json`（`Instances>0` 且地图前缀对得上） | 贴图字节按 `<root>/textures` 与 `export-quality.json` 里 `sources` 实际统计，几何按顶点/三角面换算 |
| `inventory` 只有包体积 | 只扫描过 pak，没导出过 | 最粗的一档，按 `package_bytes` 乘经验系数（源 3.2–8.0×、UE 1.4–2.6×），可能差到 2 倍 |

## 历史台账

导出成功后（主流程返回 0）会写一条记录到 `%LOCALAPPDATA%\AtlasMap\export-size-history.json`：

```json
{
  "format": "atlasmap-export-history",
  "maps": {
    "safehouse": {
      "source_bytes": 2333570958,
      "texture_bytes": 1020000000,
      "blend_bytes": 962000000,
      "ue_bytes": 0,
      "reference": 1024,
      "when": "2026-11-13 06:12:44"
    }
  }
}
```

只存字节数，不存路径，所以导出目录搬走也不影响。下次打开这张图的估算面板会看到
「按本图上次成功导出的实测大小」。

## 按实测校准的经验系数

用本机两次完整导出（SafeHouse 源 2.10 GiB / UE 0.99 GiB；ShootingArea 源 2.18 GiB /
UE 0.59 GiB）反推出来的区间：

- 源目录 ≈ 贴图 PNG × 1.75–2.45 + 几何 × 1.0–1.6（`.blend` 与 PNG 大致同量级）
- UE 项目 ≈ 贴图 PNG × 0.50–1.35 + 几何 × 0.25–0.60（BC 压缩比随 alpha/位深摆动，实测
  1.09 与 0.56 两头都见过）
- Blender 工程 ≈ 贴图 × 1.10–1.70 + 几何 × 0.9–1.3

旧版本把 UE 目标统一乘 1.7、源目录又漏掉 `.blend`，于是出现过「说 1.2 GB、实际 2.3 GB」
和「说 2.9 GB、实际 1.0 GB」两种偏差；这一版改成按实测区间给范围，并在同档位下直接给
实测值。
