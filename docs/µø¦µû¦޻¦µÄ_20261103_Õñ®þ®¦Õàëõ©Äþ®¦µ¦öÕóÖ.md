# 天空光、雾和爆破空气墙更新

更新：2026-11-03。虚幻引擎 **5.4 特殊构建版，已适配 5.4 普通版**。

## 天空光实时捕捉提示与环境光异常

当前 BombDefusal_Watch 的源天光使用指定立方体贴图。旧导入逻辑却先改成实时场景捕捉；当场景没有 SkyAtmosphere、VolumetricCloud 或可捕捉的 IsSky 网格时，UE 会显示警告，天光可能为黑。

本次补上 TextureCube 的读取和资源路径转换，恢复真实六面 HDR 天空资源。导入器保留有效指定 Cubemap，并在环境恢复后检查实际可见天空来源；没有合适来源时不再盲目启用实时捕捉。缺失资源会单独记录，关闭警告不代表已经恢复环境光。

当前关卡已绑定其源天光引用并关闭实时捕捉。源天光记录仍为强度 2；与恢复的物理曝光配套，按源配置 IBLCoef=500 做明确的原生单位适配，原生天光强度为 1000，低分辨率 HDR 背景使用同一显示换算。该换算作为兼容处理单独记录，不修改导出的源值，也不把它声称为完整画面一一匹配。

原天空模型的普通受光占位材质已单独换为 Unlit/IsSky，并取消阴影、距离场与光线追踪遮蔽。显示使用该 128 像素 HDR 立方体作为临时背景，不能当作高清天空全景已完成。

## 源文件关闭的雾被意外启用

`Mobile_UnderwaterFog` 的源 `bVisible=false` 已被状态提取保留，但旧导入器把可见性应用放在普通灯光分支里，雾组件被跳过。现已改为所有灯光/雾共用可见性恢复，并独立读回；明确 False 保持 False，源字段缺失保留兼容行为。当前关卡已关闭该层雾，其密度和颜色未被任意修改。

## 室外大面积过曝

**现象：** 室外地面、屋顶和远景大片泛白，像自发光；只降低太阳会让其他区域更暗。

**原因：** 导入后仍使用默认亮度范围 `0.03～8`，而源环境另有桌面曝光范围；源补偿曲线和测光贴图虽然保留引用，但实际资源没有导入，后处理里变成空值。光照配置和曝光配置因此不配套。

**更新：** 辅助程序按明确引用导出曝光曲线与测光贴图；导入器同时恢复可确定的桌面曝光范围、原曲线和测光图。当前地图的源范围为 EV 13.5～14.5；本工程未开启扩展亮度范围，按 UE 的换算写入亮度 11585.2375～23170.4750，不能把 EV 数字直接填进旧亮度字段。补偿由原 7 点曲线控制，不用统一减亮代替。

源文件存在动态、多组冲突或缺少必要曲线时会报告，不能任意挑一个时刻或使用移动端固定曝光值。应用后独立回读原生组件，确认范围、曲线和测光图绑定，再保存。

当前关卡已完成此修复；同一室外机位的大面积泛白明显消退。太阳保持 4500，曝光不靠任意负补偿压暗；天光按上节的单位适配与物理曝光配套，避免修曝光后天空和阴影发黑。特殊材质及高清天空的后续适配与本项曝光修复分开验收。

## 爆破模式默认移除开局空气墙

用户指出的 `C002_DFI_c508f7c2b0be49b916a94ed4` 来自 `StartBlockWall19`，其蓝图类为 `BP_BlockWall_BombDefusal_C`。这是模式用空气墙，不是建筑墙。源材质是半透明、自发光类别；导入为普通不透明材质后会表现为大块白板。

按用户要求，后续导出爆破模式地图时默认过滤这类已确认的空气墙。通过源蓝图身份识别，不按 Plane 网格名、白色材质或物件尺寸批量删除。更新同时处理显示实例与导出清单，并记录过滤数量；其他平面、建筑、道路及碰撞物件不受这条规则影响。

当前 BombDefusal_Watch 共移除 9 个同类对象，包括指定的 StartBlockWall19；删除前保留 T3D 与地图文件备份。关卡 Actor 数由 5224 变为 5215，其他物件未因本条规则移除。

## 修改位置

- `tools/scene_state/DeltaForceTextureCube.cs`：真实六面 Cube 载荷读取。
- `tools/scene_state/EnvironmentState.cs`、`Program.cs`：资源路径与独立环境导出入口。
- `tools/scene_state/scene-state.csproj`：辅助程序运行依赖。
- `tools/scene_state/ExposureState.cs`：明确引用的曝光曲线与测光贴图导出。
- `scripts/official/ue_sky_capture.py`：实时捕捉前提检查、指定 Cubemap 保留与读回。
- `scripts/official/map_exposure.py`、`ue_source_exposure.py`：桌面曝光范围、曲线与测光资源恢复。
- `scripts/official/ue_ensure_lighting.py`：天空光策略和雾可见性恢复。
- `core/export_filter.py`：默认移除已确认的爆破空气墙，保留其他平面与原几何缓冲；过滤数量写入 `filter_report.json`。
- `core/exporter.py`、`ue_pipeline.py`、`full_parallel_export.py`：普通导出、串行 UE 与并行分块出口统一接入过滤。

固定 `map-export.exe`/`dfmap.dll` 未替换。新增辅助程序和外部处理脚本需随应用一起更新，不能只替换一个 Python 文件或一个 DLL。

本轮测试包含无天空来源、指定 Cube、有效捕捉源、不可用属性、雾的 False 值与静默写入失败；实际关卡还核对了 Cubemap 绑定、实时捕捉关闭、雾显示状态及保存。回归结果与逐项诊断放在制作工作区 `out/sky_capture_fix/20261103/`。
