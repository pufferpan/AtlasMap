材质里的 Attribute 节点
======================

**症状**

导出到了「材质编译」这一步，三个并行 worker 同时退出：

```
RuntimeError: Unsupported contributing node ATTRIBUTE
Error: script failed, file: '...\scripts\official\compile_iceland_ue_materials.py', exiting.
```

前面的步骤都成功（索引、源提取、光照烘焙、场景创建、模型输出），只有材质编译整批死在
同一个节点类型上。这不是数据坏了，是编译器不认识 `ShaderNodeAttribute`。

**为什么会有这个节点**

Blender 的 Attribute 节点用来读「网格自带的属性」：顶点色（Col / Vertex Color）、
UV、或者自定义的浮点属性。UE 材质里做分层、脏迹、遮罩时经常挂一个，把顶点色乘进
Base Color 或 Roughness。地图资产里只要有一个材质这么接，整块（默认 1/3 张图）的
材质编译就会全军覆没。

**现在的处理**

`scripts/official/compile_iceland_ue_materials.py` 的 `Generator.output()` 增加了
`ATTRIBUTE` 分支：

| Attribute 节点设置 | 结果 |
| --- | --- |
| `attribute_type` 不是 `GEOMETRY` | 仍是错误（VIEW_LAYER / INSTANCER 没有意义） |
| 名字是 `Col`、`Color`、`Col0`、`VertexColor`、`VC` 或空 | 复用顶点色 `VC`：Color→`VC`、Vector→`float3(VC.r,VC.g,VC.b)`、Fac/Alpha→`VC.a` |
| 其他属性名（BakeMask 之类） | 打一行 `[atlas] WARN attribute 'bakemask' has no data source; using zero`，按输出类型退化成 `float4(0,0,0,0)` / `float3(0,0,0)` / `0.0` |

顶点色本来就在导出链路里（`VERTEX_COLOR` 分支用的也是 `VC`，并会写进材质记录的
`inputs`），所以「Col」这条能完全还原；自定义属性没有数据来源，只能退化成常量，
但不会再让整批材质编译失败。

三段代码副本都已同步：`scripts/official/`、`exporter-source/scripts/`、
`exporter-source/source/scripts/`。

**验证**

- 单测 `tests/test_material_attribute.py` 4 项：顶点色映射、Vector/Fac/Alpha 输出、
  未知属性退化成 0、非 GEOMETRY 仍报错。
- 端到端：用 Blender 5.3 跑一份带 Attribute 节点的合成工程，
  `compile_iceland_ue_materials.py` 正常产出 `material_plan.json` 与 `.hlsl`，
  记录里 `inputs: ["VC"]`、末行 `return (VC).rgb;`。
- 全量单测 335 项通过。

**顺带修的测试**

「按内存余量限制并发」加上之后，`tests/test_ue_import_memory.py` 与
`tests/test_full_performance.py` 里的容量断言会受本机设置影响（开关关掉时不再收紧），
已显式传 `limit_by_memory=True`，让这些用例只测算法本身。
