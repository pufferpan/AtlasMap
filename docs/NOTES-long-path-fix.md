# 2026-11-02.long-path-fix

修复「8/17 汇总渲染状态」将已存在的长路径烘焙资源误报为缺失的问题。

BombDefusal_Watch 的反射捕获文件已由 .NET 辅助程序成功写出，但分块内的完整路径达到 316 个字符。在本机 Windows 路径策略下，Python 使用普通路径时 `is_file()` 返回 false；使用 Win32 扩展路径可读到同一文件，大小与清单一致。

共享文件 I/O 现在在 Windows 上使用 `\\?\` / `\\?\UNC\` 路径，覆盖文件校验、JSON 读写、烘焙文件合并、硬链接及跨盘复制回退。仍检查真实路径是否位于指定分块内，并保留 SHA256 校验。缺失文件与路径越界现在分别报错。无需修改系统注册表或移动用户的导出目录。

本机保留的 6 个真实分块已重新执行渲染状态合并，得到 301 个关卡、1,131 个源包、142 个唯一烘焙载荷（172,206,731 字节）和 166 条灯光。全部烘焙载荷的大小与 SHA256 校验通过。这是第 8 步的实际验证，不代表已经完成后续 Blender / UE 导入。

回归测试覆盖超过 260 字符的真实文件、重复载荷合并、再次合并、损坏载荷拒绝、跨盘复制回退、UNC 路径和目录越界/符号链接越界拒绝。

同时修复随后单进程重试出现的 `Misplaced level ...BombDefusal_Watch_TODLight.umap: 0.1935276030562818 m`。该关卡包含缩放 10,000,000 倍的天空网格，范围约 2,884 公里；源 float32 厘米边界的一格精度已达 16 厘米。原 GLB 用双精度重算的边界也与原清单相差约 19 厘米，因此不能把这一差值直接判为 Blender 放错位置。

常规物体仍要求边界偏差不超过 5 厘米。仅当原生边界差值处于两格 float32 精度以内时，再独立重算原 GLB 顶点及完整变换，并要求 Blender 与原 GLB 的偏差不超过 5 厘米。Blender 5.2.2 实测该关卡通过，实际相对原 GLB 的最大误差为 0.000019531231 米，并成功保存 `.blend`。回归覆盖天空对象真实错位仍拒绝、普通物体限值保持，以及超过源数值精度范围的差异仍拒绝。

关闭旧版程序后，启动本版再执行导出。普通「导出」按钮仍会创建一次新任务，不会自动跳过前 7 步；已有分块和本次诊断结果可保留用于核对。
