# 多进程加速导出

版本：1.0+2026-11-02.efficient-chunks

在「进 UE」页面开启「多进程加速导出」。默认关闭，开启时显示：

> 打开此选项后导出速度会提升很多，但是资源占用也会暴涨，请考虑好

确认后播放红色环形启动特效，界面切换红色强调色。可选 2–8 个分块进程，上限随桌面空间调整。文件准备线程数仍是独立设置。

点击「一键导出到 UE」，主窗口先缩成一个窗口，再从同一位置分出多个窗口并平铺。动画使用缓存画面，后台日志持续接收；每个窗口显示本块的 PID、任务分配、资源与独立进度。F12 或双击标题可显示隐藏调试按钮，查看整机 CPU 与内存占用。

全部步骤校验成功后，所有实际工作窗口同时变为绿色画面片段，移动并拼成大幅「成功」。2–8 个窗口全部参与；点击任意片段返回各自日志，Esc 或关闭任意窗口可返回主界面。失败或取消保留错误日志，不播放成功动画。

点击任意窗口的「终止导出」立即显示停止状态，在后台批量结束本次任务的进程树，并取消排队分块。文件汇总和资源保存也检查取消标记；不会让结束进程的等待阻塞界面，也不会终止用户另外打开的编辑器。

## 执行方式

1. 快速索引源关卡，再用多个进程读取实际实例、模型和对象数量，按真实负载生成本次任务的唯一分块计划。同名基础/HD 关卡放在同块，源关卡只归一个进程。
2. 多个进程同时调用指定原版导出器 DLL 的 Merge.CmdMerge，分别提取本块几何、贴图、实例与灯光。原版 DLL 的 SHA256 强制校验；参数通过 JSON 数组传递，避免大型地图超过 Windows 命令行长度限制。
3. 多进程读取本块原始灯光、后处理、相机与模板，保留原始烘焙载荷；汇总时校验共享包一致性。
4. 多个 Blender 同时导入各自源关卡，再分别输出模型、编译材质、进行材质分组。对象、父子关系和坐标随块保留；源辅助对象的可见性、材质覆盖和碰撞信息保留。各块场景内嵌贴图，可单独打开。
5. 多个 UE 在隔离工程中导入各块，并分别还原灯光与碰撞。资源使用独立目录，防止不同进程改写同一资产。全地图光照兼容参数统一计算，公共兼容后处理只创建一份。
6. 各工作窗口独立校验并保存自己的资源与分块关卡。主关卡 LV_Map 引用全部常驻分块关卡；重新打开主关卡检查对象覆盖、坐标、父子关系、材质与灯光后，再完成各分块的最终校验和临时 UE 工程清理。

源目录、分块目录汇总和主关卡保存使用单一协调进程。几何提取、原始渲染读取、场景装配、模型输出、材质编译/分组、UE 导入/光照/碰撞及资源保存均按块并行；不会让多个 UE 同时写入同一关卡文件。

UE 临时工程放在最终工程同一磁盘的 .atlasmap-parallel/<本次任务>，完成资源以硬链接发布，清理临时副本后最终资源仍然有效。相同贴图和烘焙载荷共享不可变缓存，减少重复写盘。导出盘不足 4 GB 且工程盘空间更充足时，分块场景与传输缓存自动改放工程盘；开始导出和进入 UE 前检查实际磁盘空间。

窗口数量表示独立分块数。UE 会结合可用物理内存和提交内存限制并发数量，并优先处理资源较多的块；未启动的窗口显示排队原因。16 GB 机器通常允许同时运行两个 UE，其余块完成一个接一个继续，避免因页面文件不足而整批崩溃。不会修改系统页面文件设置。

源分块通常位于导出目录的 chunks/<本次任务>/Chunk_001；传输目录的 chunks/index.json 记录各块场景、清单和 UE 关卡的实际位置。各阶段完整日志分别保留，窗口只显示进度、警告与错误，避免刷屏拖慢界面。清单和 UE 完成报告采用原子替换，磁盘写满时保留原清单，直接报告「磁盘空间不足」。任务报告使用本次运行标识校验。失败会停止其他进程并阻止后续汇总，保留现场。

并行导出增加内存和磁盘占用，实际速度受地图规模与设备资源影响。使用 Blender 5.2.2 / UE 5.4.4 检查CollectionRoom双进程和SafeHouse八进程导出；2–8 窗口布局、成功动画和磁盘故障处理另行自动检查。
