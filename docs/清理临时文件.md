# 导出后的临时文件清理

一次导出会在几个地方留下中间产物。v1.0.14 起，**导出成功后默认自动清掉**（可在「设置 →
导出后清理」里关），也可以随时在「工具 → 临时文件 → 清理临时文件…」手动清。

## 清哪些

| 位置 | 是什么 | 大小 | 清掉之后 |
| --- | --- | --- | --- |
| `<导出目录>/preview/<run_id>/*.npz` | 视口预览缓存 | 几 MB | 没影响 |
| `<导出目录>/source-render/raw` | 分块原始 glb | 几十 MB – 数 GB | 想「重新生成 Blender 工程」需要重导 |
| `<导出目录>/*_blender/*/tasks/*.json` | 分块任务清单 | KB | 下次保存工程时会重写 |
| `%LOCALAPPDATA%\AtlasMap\job-config\*.json` | 每次导出一份导出器配置 | KB | 只留最近 20 份 |
| `%LOCALAPPDATA%\AtlasMap\logs\*.txt` | 导出日志 | 累计上百 MB | 只留最近 30 份，且总量不超过 300 MB |
| `%TEMP%\atlasmap-probe-*` | 探测密钥时的临时目录 | 空目录 | 现在用完即删 |

## 不动什么

- `split/*.glb`、`scene.json`、`merge_report.json`、`lights.json`、`source-render/textures`、
  `source-render/assets`、`source-render/environment` —— 已经导出的成果与 Blender 工程要用的素材
- 导出目录里用户自己放的文件（清理只碰上面表格里的固定路径）
- 链接（符号链接 / 目录联接）一律跳过

## 为什么默认删 `source-render/raw`

它是「把每个分块先写成 glb，再合并成 split」的中间文件；合并完成后只有「重新保存一次
Blender 工程」用得上。一张中等大小的图能到几个 GB，留着最容易让人觉得「怎么又占了几十 G」。
如果习惯反复重存工程，到「设置 → 导出后清理」勾上「保留 source-render/raw」即可。

## 旧目录怎么办

以前导出的目录不会自动追着清。到「工具 → 临时文件 → 清理临时文件…」选那个导出目录，
会先列出项数和体积再确认。只删该目录内的中间产物，导出成果不动。
