# 棋盘材质与重复 HLOD

静态导出会同时载入游戏的精细模型关卡与 HLOD 远景代理关卡。部分源 HLOD 的 Diffuse 图集本身已经包含棋盘格；将两套模型同时显示，会遮住精细模型的正常材质。检查材质是否存在、贴图参数是否绑定、着色器能否编译，均不足以发现这个问题。

导入现在按源路径匹配同一地图、同一 Runtime 分区的 HLOD0 与 Big/Mid/SmallMeshGroup。仅在相同分区已经包含可见精细模型时，将对应 HLOD 标记为编辑器和运行时隐藏。不同地图、不同分区、只有远景代理而没有精细模型的分区，以及 HLOD1 等未确认规则的层级均保留。模型、贴图和碰撞资源不删除。

普通模式和并行模式共用 `map_lod.py`；并行模式使用全图源索引判断替代关系，避免精细模型与代理被分给不同工作进程时漏判。每个分块生成 `lod_report.json`，最终汇总关卡重新检查隐藏状态，导入结果记录 `suppressed_hlod_proxies` 数量。

已打开的 BombDefusal_Dock 工程检查结果：3894 个静态模型 Actor、6835 个材质槽均有引用，134 个母材质均可编译；确认 49 个 HLOD0 有对应精细模型。当前工程已在编辑器事务中修复这些重复代理，未强制保存用户工程；可使用编辑器撤销，保存关卡后长期保留。
